# GG

关闭项目前的收尾 Skill——自动整理 `CLAUDE.md`，并同步更新 `agentmemory` 长期记忆。

## 这是干什么的

每次结束一段工作、准备关闭项目前，手动整理文档和记忆很容易漏掉、懒得做，久而久之要么 `CLAUDE.md` 一堆信息没归类，要么下次重开项目时 Claude 完全不记得之前踩过的坑。

`GG` 把这套收尾流程固定成一条命令，一次触发做两件事：

1. **整理 `CLAUDE.md`**：把本次会话中零散的规则、流程、约束分类归纳到对应分区，保留原有内容，过时的信息标注"已废弃"而不是直接删除。
2. **同步 `agentmemory`**：把本次做了什么、踩了什么坑、还有什么没做完、做了哪些关键决策，分条存进长期记忆，方便以后 `/recall` 精准搜到。

## 使用前提

- 已安装 [Claude Code](https://claude.com/claude-code)
- 已安装 [agentmemory](https://github.com/rohitg00/agentmemory) 插件，并且本地 memory server 正在运行
```powershell
  curl http://localhost:3111/agentmemory/health
```
  如果没起，先另开一个终端运行：
```powershell
  npx @agentmemory/agentmemory
```

## 安装

```powershell
mkdir "$env:USERPROFILE\.claude\skills\GG" -Force
```

把本目录下的 `SKILL.md` 放进 `C:\Users\<你的用户名>\.claude\skills\GG\SKILL.md`。

安装范围说明：
- 放在 `~/.claude/skills/GG/`（用户目录）→ 所有项目通用
- 放在项目根目录 `.claude/skills/GG/` → 仅当前项目可用，且会随项目一起进版本控制，方便团队共用

## 使用方法

工作告一段落、准备关闭项目前，在 Claude Code 会话里输入：/gg

Claude 会自动读取当前会话上下文、结合历史相关记忆，完成 `CLAUDE.md` 整理和 `agentmemory` 更新，无需额外手动操作。

## 分工原则

| | CLAUDE.md | agentmemory |
|---|---|---|
| 读取方式 | 每次开会话都全文读入 | 按需检索（`/recall`），用到才读 |
| 适合内容 | 长期有效、每次都用得上的硬性规则和约束 | 一次性的踩坑细节、调试过程、具体决策权衡 |

不要把偶发的、具体的调试记录塞进 `CLAUDE.md`，否则文件会越来越臃肿，每次开会话都要多读一堆用不上的内容；这类信息交给 `agentmemory`，需要时按关键词搜就行。

## 常见问题

**执行后发现 agentmemory 里存了重复的记忆？**
Skill 里已经要求先 `/recall` 确认是否已存过再决定要不要 `/remember`，但检索不是 100% 精准，如果发现明显重复，可以手动 `/forget` 清理。

**`/GG` 打不出来，命令没反应？**
检查文件夹路径和文件名是否正确（`SKILL.md` 必须放在 `skills/GG/` 目录下），改动后需要重启 Claude Code 或开一个新会话才会生效。也可以尝试小写 `/gg`。

**CLAUDE.md 里的旧规则被误判"已废弃"了？**
Skill 只会在**本次对话中有明确推翻依据**时才标注废弃，如果发现误判，直接手动改回来即可，不影响下次继续用。

**分工原则怎么理解？**
好,拆开来解释一下这个分工逻辑,核心是两者的读取方式完全不一样。

CLAUDE.md:每次都要读,是"固定成本"

CLAUDE.md 的机制是——每次开新会话,Claude Code 都会把这个文件整个读进上下文,不管你这次要做什么事。

打个比方:CLAUDE.md 就像你桌上摆的一本"操作手册",你每次开工前都要从头到尾翻一遍,不管今天要做的事跟手册里哪一页有关。

所以如果你把"一次性的踩坑细节"也写进去,比如:

2026年3月15日调试登录接口时，发现是因为环境变量加载顺序问题，
折腾了2小时，具体现象是xxx，后来发现是yyy，解决方法是zzz……

这种内容一旦写进 CLAUDE.md,就意味着以后每次开新会话,不管你今天是不是在处理登录相关的事,Claude 都要先把这段两小时debug的流水账读一遍。写十条这种东西还好,写一百条,CLAUDE.md 就会变得又长又臃肿,每次开会话都要多花时间、多占上下文空间去读一堆跟当前任务毫无关系的历史细节。

agentmemory:按需检索,是"按次付费"

agentmemory 不一样,它是存起来,但不是每次都读——只有当你 /recall 关键词 或者 Claude 判断当前问题跟某条记忆相关时,才会把对应的那一条或几条内容"捞"出来放进上下文,其他没用到的记忆完全不占地方、不消耗 token。

同样是那条 debug 记录,存进 agentmemory 的话:

平时开发别的功能,这条记录完全不会出现在你眼前,不占用上下文
只有哪天你又碰到类似的登录/环境变量问题,搜一下 /recall 环境变量 登录,这条两年前的记录才会精准地被翻出来
**一句话总结这个区别**
	CLAUDE.md	agentmemory
读取方式	每次会话都全文读入,不管用不用得上	按需检索,用到才读,没用到不占资源
适合放什么	长期不变、每次都用得上的规则(比如"这个项目用 TypeScript,变量命名用驼峰,禁止直接改 main 分支")	一次性的、具体的、可能只在特定场景才有用的信息(比如某次踩坑的详细过程)
不注意的后果	塞太多细节 → 文件越来越长 → 每次开会话都要多读一堆没用的东西,拖慢速度、浪费上下文	(相对没有这个问题,反正不用不读)
为什么不能反过来,全存 agentmemory 就好,CLAUDE.md 干脆不用管细节?

因为有些规则是你希望 Claude 无条件、每次都记住的,不能靠"猜关键词才能搜到"。比如"这个项目的数据库操作一律要走 ORM,禁止手写 SQL"这种硬性约束,如果只存进 agentmemory,万一某次提问没触发到相关检索(比如你问的是别的问题,但顺手让它写了段涉及数据库的代码),这条规则就没被读到,规矩就被破了。这种"任何时候都不能忘"的东西,必须放 CLAUDE.md,靠"每次强制读入"来保证不会被漏掉。

而具体的、偶发的踩坑记录,恰恰不需要"每次强制读",只需要"用得上的时候能搜到",所以更适合放 agentmemory,不占用 CLAUDE.md 这个"每次必读"的固定位置。
